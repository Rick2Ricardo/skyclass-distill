# 空中课堂蒸馏：验证型产品结构规划

更新：2026-08-09

## 结论

当前 React 前端可以支持素材导入、Skill 蒸馏、单轮 Tutor 调试和三条件并排查看，适合作为工程冒烟界面；它还不是一个适合长期研究验证的产品。

后续产品不应继续沿着“多加几个功能入口”的方向扩展，而应围绕一条可复现的研究主线组织：

```text
课堂证据
  → 可审查的 Skill 版本
  → 固定数据集与实验条件
  → 批量运行和逐例比较
  → 自动评测 + 人工盲评
  → 可导出的结论与失败案例
```

品牌和业务语言应保留“空中课堂蒸馏 / SkyClass Distill”的项目身份。TypeScript、React、Pi SDK 和 Inno Agent 式运行边界属于技术实现，不应改变产品定位。

## 最终交互形态：Codex 式教学工作台

产品分成两个相互连接、但职责不同的界面：

1. **教学运行面**：学生真正使用的默认首页。采用“左侧项目导航 / 中间教师会话 / 右侧产物画布”的 Codex 式布局。
2. **研究控制面**：总览、课堂证据、Skill 工坊和评估中心，用于准备能力和验证效果。

教学运行面不是普通聊天框。每轮会话由统一事件链组成：

```text
学生问题
  → 教师诊断
  → 读取 Skill / 检查证据 / 调用教学工具
  → 生成 Diagram、Plot、Table 等 Artifact
  → 中间栏解释，右侧画布呈现
  → 学习检查
  → 会话回放进入评估
```

工具必须经注册表显式允许；文件系统和 Shell 默认关闭。所有产物都带 `artifact_id`，所有工具调用都进入 trace。教学会话与离线评估复用同一事件和产物协议，确保“学生看到的运行”可以原样回放并接受验证。

## 当前前端适用性判断

### 已经可用的部分

- 项目作为素材、Skills 和运行记录的隔离边界。
- 素材导入、转写和蒸馏任务的基本工作流。
- Base、Text Skill、Vision Skill 使用同一模型和运行时进行单题比较。
- 展示实际模态、视觉证据数量和工具调用，能够识别多模态回退。
- 已有 24 条高中物理 P0 benchmark，可作为第一个验证数据集种子。

### 不足以支撑验证的部分

- `Tutor Lab` 与 `Experiments` 都在运行学生问题，职责重叠。
- 实验只接受一个临时问题，没有数据集、测试集切分和案例版本。
- 运行时没有显式固定 Skill 版本、Prompt 版本、模型参数和证据快照。
- 没有重复运行、随机化、盲评和成对比较，难以控制模型随机性与评审偏差。
- 没有 Rubric 版本、硬性断言、自动评分、人工评分之间的分层。
- 没有实验历史、失败案例筛选、回归比较和报告导出。
- 首页指标以素材和任务数量为主，不能反映“是否已经具备可验证条件”。

## 推荐的信息架构

每个研究项目提供一个默认教学工作台，以及四个研究控制工作区。后台任务和设置作为全局能力，不占一级导航。

### 0. 教学会话

- 左侧：项目、会话历史和研究入口。
- 中间：学生输入、教师回答、思考状态和可折叠工具轨迹。
- 右侧：受力图、坐标图、概念图、过程图及后续交互式实验产物。
- 点击工具轨迹可以在画布中重新打开对应产物。
- 新会话不污染旧会话；后续以事件流持久化并支持完整回放。

### 1. 项目总览

回答“这个项目现在能不能开始验证”：

- 研究问题、学科、学段和数据范围。
- 证据就绪度：视频、转写、关键帧、失败素材。
- Skill 就绪度：草稿、待审、已冻结版本。
- 评估就绪度：数据集案例数、Rubric、实验配置完整性。
- 最近实验、主要回归和待人工复核数量。

### 2. 课堂证据

合并当前的素材管理与证据检查：

- 素材库：视频来源、授权说明、处理状态、内容指纹。
- 逐字稿：分段文本、时间戳、人工纠错状态。
- 关键帧：画面时间、字幕邻域、视觉观察和有效性。
- 证据快照：将一组素材版本冻结为蒸馏输入，后续实验不随源文件变化。

### 3. Skill 工坊

Skill 的重点不是“有多少个”，而是“哪个版本可以接受检验”：

- 蒸馏任务：模式、模态、Prompt 版本、证据快照和运行参数。
- Skill 草稿：结构校验、证据覆盖、拒绝条件和学习检查。
- 人工审核：接受、退回、备注和需要补证据的字段。
- 版本比较：文档 diff、证据 diff、行为契约 diff。
- 冻结版本：实验只能引用不可变的 Skill version ID。

单题 Tutor 不再作为一级导航，改为 Skill 详情中的“调试运行”。它用于开发时查看 trace，不承担验证结论。

### 4. 评估中心

评估中心是未来最重要的工作区，内部采用五个页签：

#### 数据集

- 测试案例包含问题、学生状态、参考要点、错误类型、难度、是否需要视觉和来源。
- 支持 `exploration / validation / holdout` 切分。
- 支持从 JSON/CSV 导入，也能把真实失败运行回收为新案例。
- 数据集修改自动产生版本；实验必须固定到具体版本。

#### 实验设计

- 选择数据集版本和测试切分。
- 选择条件：Base、Text Skill、Vision Skill，以及后续的人工 Skill 或其他模型基线。
- 固定模型、参数、系统 Prompt、Skill 版本和证据快照。
- 设置每案例重复次数、超时、预算和失败处理。
- 选择 Rubric 版本和需要执行的硬性断言。

#### 运行与比较

- 批量运行进度、错误重试和成本/时延。
- 按案例并排比较条件输出、tool trace、引用证据和实际模态。
- 筛选失败、回退、低分、分歧大和视觉必需案例。
- 与历史实验比较，标记新增回归和已经修复的失败。

#### 人工评审

- 单样本评审：按 Rubric 对一个输出评分并写证据化意见。
- 成对盲评：隐藏条件名称、随机左右位置，只选择 A / B / 相当。
- 支持待评、已评、存在分歧和需要复核状态。
- 评审结果可反哺数据集参考答案或断言。

#### 报告

- 总体通过率、各维度得分、成对胜率和置信区间。
- 按单元、难度、错误类型、视觉需求分层。
- 硬性失败与主观质量分开报告。
- 展示代表性成功案例、失败案例和评审分歧。
- 导出 Markdown、JSON、CSV，后续再支持论文表格与图表。

## 页面关系

```text
教学会话（默认）
├── 教师对话与工具轨迹
└── 实时产物画布

研究控制面
├── 项目总览
├── 课堂证据
│   ├── 素材
│   ├── 逐字稿 / 关键帧
│   └── 证据快照
├── Skill 工坊
│   ├── 蒸馏任务
│   ├── 草稿与人工审核
│   ├── 版本比较
│   └── Skill 调试运行
└── 评估中心
    ├── 数据集
    ├── 实验设计
    ├── 运行与比较
    ├── 人工评审
    └── 报告

全局：后台任务 · 运行设置 · 导入导出
```

## 核心数据模型

```text
Project
├── SourceAsset
├── EvidenceSnapshot
├── Skill
│   └── SkillVersion
├── Dataset
│   ├── DatasetVersion
│   └── TestCase
├── Rubric
│   └── RubricVersion
└── Experiment
    ├── ExperimentSpec
    ├── ExperimentRun
    │   └── CaseResult
    ├── HumanReview
    └── Report
```

必须遵循两条约束：

1. `ExperimentRun` 创建后不可修改，只能重跑产生新 run。
2. 每条 `CaseResult` 保存模型、Prompt、Skill、证据、Rubric 和代码提交的版本指纹。

## 指标分层

### 硬性测试

- 输出结构是否合法。
- 是否真实调用了要求的 Skill 工具。
- 视觉条件是否真的读取视觉证据，发生回退时不得计入有效视觉结果。
- 证据引用是否存在、时间戳和来源是否有效。
- 是否违反 `abstain_when`、是否泄露条件或内部评测提示。

硬性测试失败意味着样本失败，不应被主观高分覆盖。

### 自动评估

- 内容正确性。
- 教学动作可执行性。
- 学习检查是否能够区分掌握状态。
- 补救是否针对学生错误。
- 场景适配和证据忠实度。
- 响应成本、延迟和工具调用稳定性。

### 人工评估

- 单输出 Rubric 评分适合定位具体问题。
- Base 与 Candidate 的盲化成对比较适合判断真实增益。
- 至少保留评论和评分理由，不能只存一个总分。

## 推荐的第一版验证流程

1. 将现有 `physics-p0-smoke-v1` 导入为 Dataset v1。
2. 从 24 条中固定 6 条 exploration、12 条 validation、6 条 holdout。
3. 冻结一组 Text Skill 和 Vision Skill 版本。
4. 创建三条件实验：Base / Text / Vision；其余模型与运行参数完全一致。
5. 每条案例至少重复运行 3 次，记录失败和多模态回退。
6. 先执行硬性断言，再执行自动 Rubric。
7. 将 Base 与 Text、Text 与 Vision 分别送入盲化成对评审。
8. 报告总体结果和按 `difficulty / error_type / visual_required` 的分层结果。
9. 把失败或评审分歧样本放入 review queue，修复后作为回归集长期保留。

## 实施顺序

### P0：先把现有能力重新归位

- 恢复空中课堂蒸馏的品牌和业务文案。
- 一级导航收敛为“总览 / 课堂证据 / Skill 工坊 / 评估中心”。
- 将 Tutor Lab 移入 Skill 调试，将当前单题 Experiments 作为实验设计的快速预览。
- 导入现有 24 条 benchmark，展示数据集列表和运行历史。

验收标准：用户能清楚区分“调试一次回答”和“运行一组可复现实验”。

### P1：补齐可复现实验闭环

- 将教学会话持久化为可回放事件流，并扩展受控工具注册表。
- 增加函数绘图、受力图、表格和交互式实验等 Artifact 类型。
- 增加 Dataset、SkillVersion、RubricVersion、ExperimentSpec 和 CaseResult 存储。
- 支持批量三条件运行、硬性断言、自动评分和失败筛选。
- 增加单样本评审与盲化成对评审队列。

验收标准：同一实验配置可以重放，并能解释任意结果使用了哪些版本。

### P2：形成研究报告和回归体系

- 增加分层统计、置信区间、成本和时延分析。
- 支持两次实验的回归对比。
- 支持 Markdown / JSON / CSV 报告和论文表格导出。
- 将人工复核后的失败案例一键沉淀为回归集。

验收标准：一次实验可以产出可复核、可引用、可再次运行的完整结果包。

## 参考依据

- Inno Agent 将 UI、应用层、未修改的 Pi Agent Runtime 和持久化状态明确分层，并将运行数据与代码目录分离；本项目应复用这一工程边界，而不是复制其学习助手产品结构：<https://github.com/hhyqhh/inno-agent>
- OpenAI 的评估流程将工作拆为定义任务、用测试输入运行、分析并迭代，说明评估应围绕可重复的任务与数据组织，而不是临时输入框：<https://developers.openai.com/api/docs/guides/evals>
- LangSmith 把 Dataset、Example、Experiment、Run 和 Evaluator 作为独立对象，并支持在同一数据集上比较多个实验：<https://docs.langchain.com/langsmith/evaluation-concepts>
- LangSmith 的单样本与成对 annotation queue 支持结构化 Rubric、盲化 A/B 比较和把人工复核结果回收进数据集：<https://docs.langchain.com/langsmith/annotation-queues>
- Promptfoo 使用测试案例、元数据和 assertions 的组合表达确定性检查与模型评分，并支持将结果导出到 CI：<https://www.promptfoo.dev/docs/configuration/test-cases/>、<https://www.promptfoo.dev/docs/configuration/expected-outputs/>

## 当前产品决策

P0 管理结构已经完成；教学端采用 Codex 式三栏工作台，不复制 EduSkill 的产品界面。当前已接入第一种受控可视化工具 `draw_teaching_diagram`，能够返回可审计 trace 和安全渲染的 SVG 产物。下一轮继续完成会话事件持久化、流式响应和更多 Artifact 类型，同时保留现有 TypeScript API、Pi Runtime 和本地数据。
